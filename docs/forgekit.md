# ForgeKit for coding agents

Every coding agent that works on MIZAN runs with [ForgeKit](https://github.com/CodeWithJuber/forgekit) (`@codewithjuber/forgekit` on npm). It adds the same checks to Claude Code, Codex, Gemini CLI, Cursor, Copilot, OpenCode and the other agents: they run as hooks, not as text in a prompt, so they still apply after a context compaction.

## What it does here

| Check | When it runs |
|---|---|
| **dep-gate** | Before an install command or a manifest edit. It blocks a package name that is not on its registry or that OSV lists as malicious. |
| **secret-redact** | After every tool call. It scrubs credential-shaped values from tool output. |
| **protect-paths** | Before an edit. It refuses to write a protected file. |
| **completion gate** | When the session stops. It refuses "done" when code moved without test evidence. |
| **session memory** | At session start and stop. It loads and saves lessons kept in the repository (`forge recall`, `forge remember`). |
| **forge-cortex** | An MCP server (`.mcp.json`) that agents query for impact, recall and the code atlas. |

## Files

The files are generated by `forge init --tools all --no-settings` and `forge hooks on`.

| File | Purpose |
|---|---|
| `AGENTS.md` | The shared rules. ForgeKit owns only the block between `forge:begin` and `forge:end`. `CLAUDE.md` imports it on its first line. Pi and Hermes Agent read `AGENTS.md` directly. |
| `.forge/forge.config.json` | The tool selection (`all`), project hooks, and `verify.exclude` (`packages/bayan` has no runnable suite). |
| `.mcp.json`, `.cursor/mcp.json`, `.vscode/mcp.json`, `.roo/mcp.json`, `.zed/settings.json`, `.gemini/settings.json`, `.kimi-code/mcp.json`, `.openclaw/mcp.json`, `.codex/config.toml`, `opencode.json`, `.continue/` | The `forge-cortex` MCP entry, plus rules for each agent. |
| `.claude/settings.json`, `.codex/hooks.json`, `.gemini/settings.json`, `.cursor/hooks.json`, `.github/hooks/forge.json`, `.opencode/plugins/forgekit.js` | Project hooks. Each one calls `forge hooks run <host> <event>`, and does nothing when `forge` is not on PATH. |
| `scripts/dev/forgekit-session.sh` | A SessionStart hook. It installs the CLI when it is missing, and upgrades it when npm has a newer release. It never fails the session. |

## Staying on the latest version

- **Cloud sessions.** The environment's setup script installs the CLI before the session starts:

  ```bash
  npm i -g @codewithjuber/forgekit@latest
  bash "$(npm root -g)/@codewithjuber/forgekit/install.sh" --no-settings
  ```

  The second command links the skills, crew and rules. `--no-settings` keeps `~/.claude/settings.json` untouched, which matters: a user-level ForgeKit install would switch the project hooks off.
- **Every session.** `forgekit-session.sh` compares the installed version with `npm view @codewithjuber/forgekit version` and installs the newer one.
- **Turning it off.** `FORGE_AUTO_UPDATE=0` keeps the installed version. `FORGE_HOOKS=0` turns all the hooks off for one shell.

## Everyday use

```bash
forge doctor           # check the wiring
forge hooks            # which agents have project hooks
forge impact <symbol>  # files an edit will probably touch
forge verify           # pytest at the root and vitest in frontend/, bound to this tree
forge vet <package>    # is this package real and not known malicious?
forge remember <name> "<fact>" && forge sync   # a lesson every agent sees
```

To change the shared rules, edit ForgeKit's `source/` in the ForgeKit repository, or run `forge remember` here, then `forge sync`. Do not edit inside the `forge:begin`/`forge:end` block.

`forge doctor` warns "settings missing" in a cloud session. That warning is expected: the hooks are wired per project, not in `~/.claude`. Do not run `forge doctor --fix` there, because it writes user-level hooks and switches the project hooks off.
