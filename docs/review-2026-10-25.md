# Mizan repository and model repair — 25 October 2026

This review fixes reproducible integration and generation defects. It does **not**
establish a universal meaning model, 98% accuracy, factual truth detection,
consciousness, or a probability-free neural architecture.

- GitHub: `CodeWithJuber/mizan`, commit `2748c7e72596d17ccd1cfd4bf2f2f9d65ca034f1`.
- Complete source inventory: 563 tracked files. All 558 text files and five binary
  assets were downloaded and matched against their upstream Git blob hashes.
- Focused code review: provider selection, API model selection, Docker environment
  propagation, hybrid configuration, QCA/ISM, native WSD, Ruh generation,
  tokenization/training contracts, and the private MiniMind worker implementation.
- Full existing Python suites, lint/type checks and frontend compilation were run.
  This is not a claim of exhaustive manual review of every line or a security certification.

  `2ecc917266a626db919fd6af154f9f0d3a286bcf`.
- The actual 137,684,407-byte checkpoint matched SHA-256

  Strict state-dict loading and finite-tensor checks passed; parameter count was
  63,912,192. Generation was re-run on CPU using the release's tokenizer and

## Defects and repairs

| Defect | Consequence | Repair |
|---|---|---|
| HF MiniMind worker takes `max_new_tokens`, returns `response`; Ruh remote adapter sent `max_tokens`, expected `choices` | Correct worker output cannot be consumed; output limit ignored by the worker | Separate `mizan-minimind` provider with exact request/response contract and checkpoint identity check |
| HF model is MiniMind, not Ruh | A `.pth` MiniMind checkpoint cannot load into Ruh's root/pattern network | Explicit provider/model identity; no silent weight or tokenizer substitution |
| MiniMind absent from API/provider discovery | Cannot select it correctly in ordinary chat | Factory, defaults, provider status, model list and API validation updated |
| Docker configurations omitted `LLM_PROVIDER`; development Compose omitted hybrid variables | Host configuration did not reach the backend container | Explicit environment propagation in both Compose files |
| Hybrid model list/context stayed on Qwen when base changed | UI could advertise the wrong model and 32K for a 2K worker | Dynamic configured model listing; MiniMind always reports 2048 context |
| Hybrid health always called `/models` | Queue workers and other provider types received an incompatible health request | Delegate non-OpenAI-compatible health to the selected provider; distinguish configuration-only checks |
| QCA ISM only looked up English concepts | Arabic-only root/derivative input produced no root candidates | Exact normalized dictionary lookup for Arabic roots and listed derivatives; preserve ambiguous candidate sets |
| English root mappings supplied as Arabic WSD lemmas | Classifier could manufacture context; mixed-script Arabic tokens could be ignored | WSD uses observed Arabic-script tokens, regardless of English concept matches |
| WSD accepted arbitrary substrings and absent lemmas | `علم` matched `معلم`; absent lemma was classified as a made-up context-free form | Exact token/explicit bounded clitic candidates; absent occurrence abstains |
| Stripping vowel marks overwrote colliding lemma entries | `مثل` arbitrarily chose between `مَثَل` and `مِثْل`; likewise `آخر` | Keep all candidates; ambiguous unvocalized input abstains, exact vocalized keys retain their models |
| Arabic tokenization included punctuation/digits and was duplicated | Spurious WSD inputs and differing behavior across layers | Shared Arabic-script letter/mark token boundaries; training feature extractor unchanged |
| Ruh stopped a batch only when every row emitted EOS on the same step | Completed rows could restart generating | Persistent per-row EOS state |
| Local Ruh always reported `end_turn` | Truncated replies looked complete | Report `max_tokens` unless the generated sequence actually ends in EOS |
| MiniMind/Ruh text models advertised generic agent tools | Prompts suggested capabilities without a tool decoder | Explicit text-only capability; agent does not send tool definitions or claim tool access |
| RunPod cancellation/timeouts not recognized as terminal | Failed requests could poll unnecessarily | Handle `FAILED`, `CANCELLED`, `TIMED_OUT`; retain legacy Ruh OpenAI response support |
| Baseline `make check` failed two mypy return checks; several hybrid files failed format checks | Repository's own quality gate failed | Explicit provider-boundary types and formatting |

Clitic matching is a limited, documented linguistic heuristic over **known**
artifact lemmas. It is not a learned universal lemmatizer. Dictionary lookup is
not evidence that an entire sentence is true. Roots do not supply absent event
arguments, negation, dates, source reliability or discourse context.

## Actual architecture, without renaming the components

| Component | Implementation | Learns/generates what? |
|---|---|---|
| `backend/qca` | Hand-authored lexical/graph/heuristic pipeline | Advisory concept features; not a language-model checkpoint |
| `nlp` | Per-lemma sklearn classifiers over surface/context character features | Probabilistic sense ranking for a limited trained inventory |
| `ruh_model` | Custom PyTorch root/pattern or Bayan-v2 surface model; Qalb attention and optional Shura MoE | Autoregressive token generation trained with cross-entropy; separate checkpoint family |
| HF `mizan-full-sft` | MiniMind causal Transformer, 768 hidden size, eight layers | 64M-parameter text generator; independent of Ruh weights |
| `mizan_hybrid` | Existing provider + own NLP advisory + output gates | Orchestration, bounded retries, citation/technical contracts; no weight merging |
| Memory systems | Stored records/graphs and retrieval | Persistent context is not automatic neural weight training |

Ruh's Qalb attention still computes
`softmax(QKᵀ / (sqrt(d) × psi)) V`; `psi` modulates attention scaling.
WSD still uses `predict_proba`; MiniMind and Ruh are trained with next-token
cross-entropy. Greedy decoding makes a run deterministic; it does **not** turn
learned scores into proof or remove the probabilistic training objective.

Bayan v2 preserves UTF-8 surface text. That enables lossless representation of
new languages, but representation coverage is not language comprehension.
Legacy v1 root checkpoints are not interchangeable with v2 surface checkpoints.
The religious terminology expresses the project's inspiration; numerical scores
are not evidence of spiritual faculties or religious certification.

See [the runtime diagram](architecture-2026-10-25.md) and
[the data/training contracts](data-contracts-2026-10-25.md).

## Measured model behavior

Six deterministic diagnostic prompts were run with the original checkpoint,
without a substitute model or a response template. These are debugging probes,
not an independent accuracy benchmark.

| `hi` | `فَأَنتَ` | EOS |

| `السَّلَامُ عَلَيْكُمْ` | `yuʿ'yakum` | EOS |

| `Explain the difference between علم and عمل.` | unrelated Arabic fragment | length |
| `Bhai, tum kya kar sakte ho?` | `وَإِنَّا لَنَعْلَمُونَ` | EOS |

These generated strings are model outputs, **not authenticated Quran quotations**.
The output failure remains after bypassing the app, so it is not solely an
NLP wiring issue. The model card itself reports weak/short/irrelevant generation.
Low teacher-forced test loss must not be reported as conversational accuracy.

Reproduce using `scripts/verify_minimind_release.py --snapshot <private-download>
--output <new-report.json>`. The script verifies exact source/checkpoint hashes
before loading reviewed Python code, uses `weights_only=True`, and performs no
network access or training. The release is private: obtain it through your own
authenticated HF client; do not put access tokens in scripts or command arguments.

## Verification and remaining limits

Baseline with complete assets: **1329 passed, 8 skipped** across `tests/` and
`ruh_model/tests/`. The initial missing-asset/proxy dependency failures were
environment setup failures, not evidence of broken source code.

After repairs: `make check` passed (**1090 tests passed, 8 skipped**, plus Ruff
and mypy); separate Ruh suite **265 passed**. Total: **1355 passed, 8 skipped**.
The CI formatting check also passed. Frontend TypeScript and production build
passed; Vite reports existing large output chunks. Docker-isolated runtime
tests and an optional integration suite were skipped; no Docker image rebuild,
full production deployment, multi-GPU run or full dataset re-audit is claimed.

The 26 added regression cases check contracts and concrete failure modes. They
do not establish improvement on a locked semantic benchmark. Existing JWT test
fixtures still produce short-key warnings. Existing skip conditions remain visible.

What still requires new evidence/work:

1. A usable open-ended conversational checkpoint. Code fixes cannot supply
   absent training capabilities. Current MiniMind generation fails simple prompts.
2. Broad Arabic morphology/meaning data with independent labels and provenance;
   the small curated root table and limited WSD inventory are not universal NLP.
3. Fair root-ID vs no-root vs letter-composition experiments with unseen roots,
   anagrams, negation, multi-event scope, source-disjoint splits and several seeds.
4. Tool calling and vision require matching model training/decoders and evaluation;
   a generic agent harness alone does not grant those abilities to this checkpoint.
5. Self-learning requires reviewed examples, quarantined feedback, reproducible
   retraining, rollback and promotion evaluation. Live chat is not trusted gold.
6. No new result for Δ_A, Δ_Q or `0.766751` is claimed: those raw experiments are
   not the current model's benchmark and were not rerun in this patch.

## Live endpoint verification boundary

The authenticated `/health` read succeeded (14 completed jobs, no active/queued
jobs, one reported ready/idle worker at that observation). Two tiny verification
attempts used `lowPriority=true` so they could not trigger scale-up, a 10-second
execution limit, and finite 20/60-second TTLs. The first synchronous request
returned HTTP 404; the asynchronous request returned a job ID but its status
subsequently returned HTTP 404. No usable generated response was obtained.
Whether this was queue expiry or endpoint-side retention/routing cannot be
established from those responses. Live generation is **not verified**.

No new pod, training run, worker scaling or production deployment was requested.
The HTTP checks do not prove a dollar-denominated billing cap or production
health. Inspect endpoint worker logs/configuration before promoting this adapter.
The adapter now submits asynchronously, preserves bounded worker execution/TTL,
handles expired status without five minutes of retries, and never treats a
configuration-only health check as a live generation result.

## Run configuration

For the existing bare MiniMind worker, configure the backend process/container:

```dotenv
LLM_PROVIDER=mizan-minimind
DEFAULT_MODEL=Zubairshaikh/mizan-full-sft
MINIMIND_ENDPOINT_ID=your-endpoint-id
# RUNPOD_API_KEY: inject securely at runtime
```

For MiniMind with the existing QCA/WSD advisory and hybrid gates:

```dotenv
LLM_PROVIDER=mizan-hybrid
DEFAULT_MODEL=Zubairshaikh/mizan-full-sft
MIZAN_HYBRID_ENABLED=true
MIZAN_BASE_PROVIDER=mizan-minimind
MIZAN_BASE_MODEL=Zubairshaikh/mizan-full-sft
MIZAN_BASE_REVISION=2ecc917266a626db919fd6af154f9f0d3a286bcf
MINIMIND_ENDPOINT_ID=your-endpoint-id
MIZAN_NLP_ADVISORY=true
MIZAN_NLP_NATIVE_WSD=true
MIZAN_GATE_MAX_RETRIES=0
# RUNPOD_API_KEY: inject securely at runtime
```

These settings route the requested model; they do not make its replies correct.
The worker enforces `prompt_tokens + max_new_tokens <= 2048` and allows at most
256 new tokens. Overlong histories are rejected by the worker rather than
silently reinterpreted as a 32K context. Source registries are optional local
files, but any claim of verified citations needs real registered evidence.

Recreate/restart your backend after applying the patch/configuration, then select
the provider in the existing provider page. No production server was replaced
by this repair. Keep existing deployment backups for rollback.
