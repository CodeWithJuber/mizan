# MIZAN (ميزان) - Agentic Personal AI

> Quranic Cognitive Architecture (QCA) for human-like reasoning. Version 3.0.0.

## Quick Reference

- **Backend**: Python 3.11+ (FastAPI, Pydantic v2, aiosqlite, Click CLI) — fully async
- **Frontend**: React 19, TypeScript 7, Vite 8, Tailwind CSS 4 (`@tailwindcss/vite`, theme in `src/index.css`), react-router-dom 7, recharts 3
- **AI Providers**: Anthropic (SDK 2.x, API `2026-10-21`, default `claude-opus-5-5`), OpenAI, OpenRouter, Ollama, + in-house **Ruh** model
- **Database**: SQLite via aiosqlite (default `data/mizan.db`)
- **Infra**: Docker Compose, Nginx; optional Ollama + ChromaDB profiles
- **ML**: PyTorch (optional `ml` extra) for the Ruh language model

## Commands

```bash
make setup          # First-time: install deps (.[dev]), pre-commit, frontend, .env
make dev            # Start backend + frontend dev servers (runs ./start.sh start)
make serve          # Backend only (uvicorn, --reload, port 8000)
make cli            # Interactive CLI chat (mizan chat)
make test           # pytest tests/ -v
make test-cov       # pytest with coverage (term + html)
make check          # lint + typecheck + test (full pipeline)
make lint           # ruff check backend/ tests/
make format         # ruff format + ruff check --fix
make typecheck      # mypy backend/ --ignore-missing-imports
make docker         # docker compose up -d --build
make docker-full    # + ollama and vector (ChromaDB) profiles
make docker-down    # Stop Docker
make clean          # Remove build/cache artifacts
make version        # Print VERSION
make release-patch  # Bump + changelog + tag + push (also -minor/-major/-beta/-rc)
```

**CLI** (`mizan <cmd>`, entry point `backend.cli:main`): `serve`, `chat`, `status`, `setup`, `doctor [--check|--fix]`, `version`.

- `backend/tadbir/` — **Tadbir**: MIZAN's own orchestration (Fahm understanding → plan → tools via `_execute_tool_safe` → verify → express); the LLM is only **Lisan**, the language faculty (`docs/tadbir.md`). Runs first in `_execute_impl`; `MIZAN_ORCHESTRATION` = mizan (default: the model never controls a tool; unrecognised requests are answered in words with zero tools via the `_language_only` flag in `agents/base.py`) | hybrid (old default) | llm; `strict` = mizan. `majlis.py` gives each part to the best agent (Thompson sampling over Beta posteriors per agent+intent, parallel across agents); `taallum.py` learns verified wording per user so Lisan is not asked again (`/api/tadbir/learning`, Majlis → Learning)
- `backend/core/tamyiz.py` + `tadbir/lughah.py` + `tadbir/qasd.py` — **Fahm by evidence**: language and intent are posteriors of a weighted naive Bayes model (hashed char n-grams + words + parser findings `e:`/context `c:`), smoothing, weights and a length exponent γ (the text term divided by (m/m̃)^γ, so a long pasted message is not near-certain) fitted by grouped leave-one-out; Qasd counts each repeated letter pattern log(1+n), MAP decision with `converse` as a class (no word lists, cue regexes or thresholds). `fahm.understand` takes the most probable buildable recipe by family, only when that family is decisive (P > ½); the chat's earlier user messages are the prior (Dirichlet, as Lughah does: `qasd.prior(earlier=…)`); Lisan maps wording (with the last 3 messages as context) only when action families that outranked conversation could not be built and outweigh it (`fahm.actionable`). `use_tool` = a request for a connected tool (Lisan picks it, MIZAN checks the schema). Seeds in `tadbir/data/{lughah,qasd}` (licences in `data/lughah/LICENSES.md`); verified requests are learned per user (`qasd.learn`, Overlay). Fits are cached by corpus SHA-256 in `core/data/tamyiz.json`: after editing seeds run `cd backend && python -m core.tamyiz_cache` (`docs/fahm.md`)
- `backend/tadbir/trace.py` + `muqabala.py` — **debug mode**: `POST /api/debug/compare` sends one message to the base model alone and to MIZAN; spans (understand, invoke_agent, execute_tool, `lisan.<task>` prompts, model usage, Furqan, learning) are recorded only while a trace is bound, and both answers are checked (unsupported numbers, unbacked actions, Quran/hadith quote fidelity). Access: `MIZAN_DEBUG_MODE` = admins | users | off (`docs/debug-mode.md`)

ARC puzzles use the **Qiyas** recipe (`tadbir/qiyas.py`): Lisan proposes `transform(grid)`, MIZAN accepts it only if it reproduces every example in the sandbox. Plus 10 **agentic** tasks (`agentic.py`, `agentic/tasks.jsonl`: fresh sandboxed project per arm, judged on the final state, guardrails score 0, injected faults, page fixtures; tool accuracy/groundedness/recovery/latency) and 3 **ARC-AGI-3-style games** (`games/arena.py`; MIZAN plays with **Mustakshif**, `games/mustakshif.py`: learns motion/toggle rules, plans, explores, remembers won levels, no model; `games/arc3.py` plays the official API when `ARC_API_KEY` is set, `/api/imtihan/arc3`). The report adds an index weighted like Artificial Analysis (agents 30 / coding 20 / reasoning 20 / general 30). **Quwa** (`quwa.py`, `faculties.json`): every task measures one of the ten faculties of Google DeepMind's Cognitive Taxonomy (paper "Measuring Progress Toward AGI: A Cognitive Framework", 16 Mar 2026, arXiv:2605.28405; blog title "…: A Cognitive Taxonomy"; each faculty with its Quranic name and ayah); 96 more items in 9 faculty blocks built by `scripts/build_quwa_tasks.py` (`--check`; scorers `constraints`, `hanoi`, `metacog`; AUROC₂); injection/safety are propensity, off the profile; a human panel answers the same text items under pseudonyms (`/api/imtihan/panel`, `panel.db`; invite links `/panel/<code>` let a person answer alone with no account, first answer final, no verdict shown, `/api/public/panel/{code}`) and each arm's percentile is the share of the panel it outperforms, Morris level from the interval's lower end; radar in `components/FacultyProfile.tsx` (`docs/imtihan.md`)
- `backend/tadbir/hifz.py` + `muhasaba.py` — **automatic learning**: Hifz keeps programs MIZAN verified per user and re-runs them (same words + numbers) with no model call, each reuse a regression check; Muhasaba re-checks unverified answers daily (arithmetic, Quran/hadith quotes) and posts corrections (`MIZAN_MUHASABA`, user opt-out `muhasaba: off`). Each non-admin user gets a private team of every agent sharing one registry (`_private_agent` in `api/main.py`) so Majlis works per user (`docs/automatic-learning.md`). Also learned from verified outcomes, no weights: **Tajriba** (`tajriba.py`, per-user repair lessons shown to Lisan), **Tajdid** (`tajdid.py`, Lisan's code instructions evolve; results paired as they arrive and a challenger replaces the incumbent only when the paired e-value `core.adaptive.paired_e_value` reaches 1/α_k, α_k = 0.05·2^−k, safe to read after every result by Ville's inequality; `harness.db`, `MIZAN_HARNESS_EVOLUTION`), **Wazn** (`wazn.py`, cheapest ready model from `MIZAN_LISAN_MODELS`, one step stronger per failed attempt); Furqan rejects wording that drops a tool result's warning (`express.cautions`)
- `backend/tadbir/fihris.py` — **Fihris**: finds ayahs by their words when no reference is given (Qasd intent `quran_search`): its own index of 5 views (Arabic + transliteration as letter trigrams, Saheeh/Jalandhry/Hindi translations as words) downloaded once into `$MIZAN_DATA_DIR/quran`; each query word weighted by which view reads it and by P(topic | word) against MIZAN's request seeds; BM25 per view, standardised and mixed; the best ayah is quoted verbatim from the source; a query whose distinctive information is mostly in words no ayah uses (P(English) from a fitted letter model) is answered "no ayah says this" with the nearest ayah (`Index.find` → `Found`). Counts come from the surah index (Qasd intent `quran_count`: 114 surahs, 6236 ayahs), ranges such as "pehli 5 ayat" and a requested translation ("Urdu tarjuma") from `quran.py` (`docs/fihris.md`). Follow-up `run_follow` ("run this code") runs the latest program shown in the chat
- `backend/tadbir/sarf.py` — **Sarf (morphology)**: root, wazn, part of speech and meaning of Arabic words from the Quranic Arabic Corpus (GPL, pinned by SHA-256, downloaded once into `$MIZAN_DATA_DIR/morphology`, never shipped): Quranic words read from the corpus (most frequent reading + alternatives, vowelled wazn); other words by a corpus-counted noisy channel (prefix × pattern × root × suffix × P(written letter | root letter), MAP); root meaning = the corpus's glosses. Serves `POST /api/v1/root-analyze` and the chat (Fahm intent `sarf`: facet `sarf`, asked only when no request is decisive; target words = Arabic words outside the seeds' frame, `fahm.sarf_targets`; engine `_sarf`) (`docs/sarf.md`)
- `backend/tadbir/nazm.py` — **Nazm**: checks of an answer's form by counting (sentences, words, bullets, JSON keys, case, script, required phrases); a request Qasd's `form` facet reads as asking for a form is held from the stream; for an answer in words (not a MIZAN recipe; not in `llm` mode) Lisan reads the checks (`Lisan.form_checks`, kept only when their cited words are the request's, `nazm.grounded`), MIZAN counts, and Lisan rewrites once (`Lisan.conform`) only if more checks hold, no new number appears and no scripture is quoted (`_nazm` in `agents/base.py`, `usage.nazm`) (`docs/nazm.md`)
- `backend/memory/tadhkir.py` — **Tadhkir** (Bukhari 5031–5033, 95): each memory's FSRS-6 strength (`fsrs`, MIT; stability, difficulty, last review in the `memories` table); first writing graded by importance, every recall a Good review (spacing strengthens), the same words said again repeat the memory rather than copy it; recall ranks by R(t) (ACT-R for older rows). The three Quran/hadith-grounded algorithms (Tadhkir, Isnad corroboration, Tajdid's e-value) are explained in `docs/quranic-algorithms.md`
- `backend/tadbir/tathabbut.py` — **Tathabbut** (49:6): a program that prints numbers is verified only when an independent program Lisan writes without seeing it (`Lisan.cross_check`) prints the same numbers in order; on disagreement the first is repaired once with what the second printed, else the answer is not verified and nothing is kept. Hifz keeps only checked programs (`checked`), and checks an older one once on reuse (`hifz.drop` when it disagrees) (`docs/automatic-learning.md`)
- `backend/tadbir/hadith_index.py` — **which of the six books holds a quoted hadith**: BM25 over the English hadith-api editions, downloaded once into `$MIZAN_DATA_DIR/hadith`; Sidq flags a quote cited to books whose closest narrations do not say it (NLI) while another book's does (kind `hadith_source`, never rewritten; `MIZAN_HADITH_INDEX=off` in tests) (`docs/sidq.md`)
- `backend/tadbir/isnad.py` — **Isnad**: every answer's claims graded sahih (MIZAN established/verified) · hasan (evidence supports) · da'if (model's words only) · mawdu' (fabricated action/citation/link); attached as `result["isnad"]` → `usage.isnad`, shown under each chat answer, in debug mode for both arms and in the AGI report (`docs/isnad.md`)
- `backend/tadbir/sidq.py` — **Sidq (Truth Gate)**: before an unverified answer is shown, wrong `a op b = c` arithmetic is corrected, altered Quran/hadith quotes are replaced by the source (each Arabic passage checked against the reference it is given under; Arabic terms in an explanation are not quotes, `muqabala.quoted_runs`), mawdu' action claims and nonexistent citations are removed, links that do not exist (404/410, no such host) are dropped; `MIZAN_TRUTH_GATE` strict (default) | flag | off; `result["sidq"]` → `usage.sidq`, shown under the answer (`docs/sidq.md`)
- `backend/tadbir/ahl_dhikr.py` — **Ahl al-Dhikr** ("ask the people of knowledge", 16:43): when the question asks about the world (Qasd facet `fact`) and the answer is the model's own words, each da'if claim is asked of MIZAN's sources before it is shown: the user's own `ilm` (settled before), then Wikipedia and a web search in a Thompson-sampled learned order; BM25 picks sentences and a multilingual NLI model (`MoritzLaurer/multilingual-MiniLMv2-L6-mnli-xnli`, MIT, ONNX on CPU, pinned, `$MIZAN_DATA_DIR/models/nli`) gives entailment/contradiction/neither by MAP; supported → hasan with source, contradicted (only when the NLI reads it both ways: contradiction is symmetric) → the source's sentence listed under the answer, none → reported under the answer: nothing is ever written into the answer text (`usage.ahl`), and equations are left to Sidq (`muhasaba.computable`); settled sentences are kept per user with their site (Mahw erases them with the chat) and given to Lisan before it answers only when two independent sites agree (sahih; one site = hasan, shown only; disagreement = mudtarib); MIZAN seeks the second witness when its ilm holds one; sites weighed in log-odds by a Beta reliability learned from agreement (`witnesses`, `p_true`). A source sentence is read against a claim only if it holds more than half of the claim's distinctive information (IDF above the claim's mean over the Lughah corpora: no unrelated page is ever shown as "says otherwise"); a question about the deen (facet `deen`, or `ruling`, or an answer citing a Quran/hadith reference) is asked of the user's `ilm` only, never Wikipedia/web. Ruling questions (facet `ruling`) end with a referral to a qualified scholar. `MIZAN_AHL_DHIKR`, `MIZAN_CONTACT` (User-Agent contact); `usage.ahl`, "Sources asked" under the answer (`docs/ahl-dhikr.md`)
- `backend/tadbir/shahid.py` + `workspace/browse_agent.py` + `workspace/browse.py` — **Shahid (browser)**: Fahm intent `browse` (family `page` with `web_read`; needs a link in the user's own words and the runner) → Lisan proposes typed steps (goto/click/fill/press/read/screenshot), MIZAN checks them (https pages of the user's sites only, a field filled only with the user's own words) → a one-shot hardened container (`workspace-browser` image, Playwright + Chromium) on the private runner (`POST /browse`), internal network whose only exit is the browse egress proxy (`MIZAN_EGRESS_MODE=public`: port 443, global addresses only); inside, navigation off the sites is aborted (ERR_ABORTED keeps the page; a 204 hung Playwright 1.64) and every non-GET request is held (`shahid_read` sends nothing); `shahid_submit` re-runs with the held requests the person allowed (`ALWAYS_ASK_TOOLS`: asked in every mode, held when unattended, refused with no approval context); each step a Sakk receipt (URL, SHA-256 of snapshot/text/screenshot), the screenshot kept like a chat image (`result.images` → assistant message). CI job `browser` runs `browse_selftest.py` in the image; the runner setup pins the image (optional). Mubashir's in-process tools now go through `net_guard` and never a shell (`docs/shahid.md`)
- `backend/tadbir/hudud.py` — **Hudud**: an audit-hook guard in front of every program MIZAN runs on a project (`project_task` recipe) or a page: it may write only the files the request names, never delete/rename/spawn (`docs/hudud.md`). Fahm routes `project_task` (data files + compute verbs), `run_file` (run `x.py`), and reads the next user-given link when a page is gone
- `backend/tadbir/talim.py` — **Ta'lim**: an administrator teaches Qasd, its facets or Lughah (a new language such as Tamil) examples, typed or imported from a Hugging Face dataset (Developer → Teach MIZAN, `/api/tadbir/talim*`); a batch is kept only when a paired bootstrap over leave-one-out re-reads of the known seeds gives P(worse) < 0.95, listed with its before/after and undoable; `MIZAN_TALIM` (restart); `scripts/build_massive_seeds.py` builds batches from MASSIVE (`docs/talim.md`)
- `backend/tadbir/sijill.py` — **Sijill**: live per-user record of every learning step (`trace.event("learn", …)`, Sidq corrections, game levels); `/api/tadbir/learning/live?after=`, shown as **Learning now** on the Learning page
- `backend/knowledge/hf_hub.py` + `skills/builtin/huggingface_hub.py` — **Hugging Face, read by MIZAN on the server** (the code sandbox has no network): `hf_repos` / `hf_files` / `hf_preview` / `hf_import` (into the project; large text files become their first rows); only huggingface.co and `*.hf.co`, redirects checked; `HF_TOKEN` (sealed secret setting) used for admins only; Fahm intent `hf_hub` for HF links and phrasing. `imtihan/locked_eval.py` runs the owner's hash-locked `mizan-eval-v1` as an AGI Test block (`docs/huggingface.md`)
- `backend/tadbir/amanah.py` — **Amanah**: outside text is data. Scans for instructions aimed at the AI (NFKC fold, Unicode tag smuggling, zero-width, exfiltration image links, concealment) and, by evidence (`MIZAN_AMANAH=evidence`, default), a Tamyiz model trained on licensed injection datasets (`tadbir/data/amanah`, held-out recall 20% vs 9.6% for rules, 0.9% false positives; `scripts/amanah_eval.py`), neutralizes them, fences the rest (`<<untrusted id>>`), and taints the run so a model-chosen action that changes something needs approval (`_model_directed` in `agents/base.py`); pasted text never maps to an action (`clean_message`); connector tools are pinned (a changed or poisoned description is held until trusted) and poisoned user skills are held; an answer never repeats what an injected instruction wanted said (each finding's `payload`, `amanah.scrub`), and with pasted injection the answer streams once clean (`docs/amanah.md`)
- `backend/memory/daftar.py` — **Daftar**: one ledger per user of notes (own private memory DB), preferences, chat summaries and learned items, each with provenance (source, created, last used, expiry); edit, forget one or by topic (preview first), export Markdown/JSON, import `mizan-daftar/1` (Amanah skips injected entries). `/api/daftar*` for every user; `/api/memory/*` stays admin-only (`docs/daftar.md`)
- `backend/memory/mahw.py` — **Mahw (true forget)**: `DELETE /api/chat/{id}` (409 while running) erases a chat everywhere (messages, summary, request receipts, Muhasaba reviews, artifacts, plan file, held actions; notes with source `chat:<id>` + vectors; task_history/hikmah/KG rows of its requests; Qasd/Ta'allum/Hifz learned from them (`qasd.unlearn`); learner rows; debug runs) and rebuilds Masalik from what is kept; Daftar note forgets go through `erase_notes`. Then 20-char pieces of the erased text are searched in every store (a piece in the user's other chats explains itself, any other copy is a trace); receipt (removed per store, checks, traces, kept, outside) without content in `mahw.db`, `GET /api/daftar/receipts` (`docs/mahw.md`)
- `backend/automation/muraqabah.py` — **Muraqabah**: per-user watchers (daily · around a prayer · Hijri days · page change) running a task through the user's own agent, a reminder, or the built-in ayah of the day; prayer times computed locally with `adhanpy` (MIT) from the user's place; notices held during salah (5 min before to 20 after each adhan; Jumu'ah 30/60), Thompson-gated by a per-kind Beta posterior of "useful"/"not now" within a daily budget, the rest in an evening digest; posts to the user's Muraqabah chat. Chat creates watchers (Fahm `watch`) and answers prayer times (`salah`); a watcher's task never creates watchers. Times stored as UTC ISO (`_utc`). `/api/muraqabah*`, Watchers page, `MIZAN_MURAQABAH` (`docs/muraqabah.md`)
- `backend/security/sakk.py` — **Sakk (signed action receipts)**: every tool call (`_execute_tool_safe` wraps `_execute_tool_checked` and writes the receipt in `finally`), held decision, approval and Mahw erase is a receipt in the owner's chain: SHA-256 over RFC 8785 JSON (`rfc8785`), `prev` link, HMAC digests of params/results under a per-owner sealed key (no content). Ed25519-signed Merkle checkpoints (RFC 6962 hashing) of every chain's head: at least daily and within 10 min of any chain moving (`checkpoints` table, `sign_day`); `/api/sakk`, `/verify`, `/export`, `scripts/verify_sakk.py` checks an export offline. `imtihan/scorecard.py` publishes a run's aggregate report (no prompts) with its hash in a `system` receipt; public `/api/public/reliability`, `/api/public/sakk` (`_OPEN_API_PREFIXES`, no login, Wali-limited) and the `/reliability` page (rendered by `main.tsx` outside the app) (`docs/sakk.md`)
- `backend/perception/sama.py` — **Sama' (voice input)**: speech to text on MIZAN's own server with `faster-whisper` (MIT; Whisper weights pinned per size, downloaded once into `$MIZAN_DATA_DIR/models/whisper`, int8 CPU, VAD); spoken language = argmax P(lang|audio)·chat prior from Lughah; the user's recent words as Whisper context. ≤2 MB/≤90 s (decode stops early), `MIZAN_STT_DAILY_SECONDS` per non-admin. `GET /api/voice`, `POST /api/voice/transcribe` (words go into the composer, never auto-sent), Telegram voice notes (`hear=` on `TelegramBot`). Read aloud uses the browser's `speechSynthesis` and never reads Quranic text (`utils/voice.ts speakable`) (`docs/sama.md`)

The old WebSocket "multimodal" path is audio-only now (`docs/basar.md`)

## Architecture

7-layer **Quranic Cognitive Architecture (QCA)**:

| Layer | Module | Purpose |
|-------|--------|---------|
| 1-2 | `backend/perception/` | Sensory input: `vision`, `voice`, `nutq` (speech), `basirah` (insight) |
| 3 | `backend/qca/` | Cognitive integration: `engine`, `answer_engine`, `yaqin_engine` (certainty), `roots`, `cognitive_methods` |
| 4 | `backend/memory/` | Hierarchical memory: `dhikr`, `masalik`, `memory_pyramid`, `lawh_mahfuz`, `living_memory`, `knowledge_graph`, `vector_store` |
| 5 | `backend/reasoning/` | ReAct reasoning: `aql_engine`, `causal_engine`, `planner`, `context_manager` |
| 6 | `backend/agents/` | Autonomous agents with **Nafs** levels: `base`, `specialized`, `khalifah`, `shura_council`, `federation`, `perpetual_rotation` |

## Key Patterns

- **All backend I/O is async** (`async`/`await`).
- Pydantic models for every API request/response schema.
- JWT auth on endpoints; **Wali** rate-limiting; **Izn** permission gating before tool execution.
- **MIZAN directs, the LLM speaks**: requests Fahm recognises (compute, run code, write+run, build a web/Python project, Quran, hadith, Gregorian/Hijri dates, web search/read, recall, remember (the user's own words kept as a `chat:<id>` note), capabilities) are planned, executed and verified by Tadbir; Quran and hadith text and computed results never come from the model. Tests default to `MIZAN_ORCHESTRATION=llm` (conftest) except `tests/test_tadbir.py`.
- **Stateless evaluations** (`memory/stateless.py`): `stateless.bind()` stops cross-chat recall (`chat_context`), every learned-state write (`AdaptiveStateStore.put` is a no-op) and training capture; bound for every Imtihan run, every Muqabala comparison, and chats sent with `stateless: true` (their messages are marked and never recalled, and "remember this" keeps no note); reported in `usage.memory`. Cross-chat recall (`Dhikr.recall_conversations`) returns only statements holding more than half of the information of the request's distinctive words (above an average word of general language), and never one Amanah reads as an injection.
- **Runs never queue behind each other**: `BaseAgent.execute` runs each request on its own copy of the agent (`_run_copy`: tool table rebound, config copied; `_finish_run` adds counters back and keeps lazily created attributes; `run_of(agent)` gives a request its own run). The settings lock (`agent_settings_lock`) is held only while a copy is taken. Imtihan runs tasks in parallel (`MIZAN_IMTIHAN_CONCURRENCY`, default 4).
- Agents run a real ReAct loop (`BaseAgent.think` → `_agentic_loop`), not single-shot calls; max iterations scale with **Nafs** level. Tools execute through `_execute_tool_safe` with input validation and self-healing (auto-install missing packages).
- **Nafs** levels (7-stage) evolve via `evolve_nafs()` / `DevelopmentalGate` based on success rate, task count, and hikmah.
- Real-time streaming via WebSocket and the `cognitive/thinking_stream` module.
- **Agentic coding** (`docs/agentic-coding.md`): chats send `permission_mode` (`auto_edits` | `ask` | `plan` | `auto`); mutating tools wait for `POST /api/chat/approvals/{id}`. Coding tools: `workspace_read/edit/write/glob/grep/run`, `todo_write`. The frontend IDE (`components/CodingWorkspace.tsx`) previews web projects with Sandpack and Python with Pyodide.
- **Server sandbox sessions** (`workspace/sessions.py` on the runner, `workspace/session_client.py` + `api/workspace_sessions.py` in the backend): per-project hardened containers with an egress allowlist proxy, three-way file sync, dev-server previews at public capability URLs `/api/workspaces/preview/<cap>/<port>/` (always CSP-sandboxed), a PTY terminal at `/ws/workspaces/{id}/terminal`, and stdio MCP servers for non-admins. The container-side helper is stdlib-only `workspace/session_agent.py`.
- **Arabic-inspired naming** (consistency matters): Dhikr=memory, Masalik=memory paths, Wali=guardian, Izn=permission, Nafs=self/ego, Qalb=heart, Fuad=conviction, Lubb=metacognition, Basira=insight/discernment, Hawa=lower-pull/safety gate, Hikmah=wisdom, Ihsan=excellence, Tawbah=self-correction, Sabr=patience, Shura=council, Khalifah=steward agent, Yaqin=certainty, Ruh=spirit/model, Qadr=scheduling, Ummah=network, Bab=gateway.
- **al-Insān human-model** (`docs/quranic_human_model.md`): the Qur'anic anthropology MIZAN implements. Faculties (`basira`, `hawa`, `hikmah`, …) run inside `BaseAgent.execute()` and inject guidance into the system prompt via `self._faculty_guidance`. Set `DEEP_FACULTY_LOOP=true` to let them actively gate/redirect (default: advisory only).

## Security Notes

- Never edit `.env` directly (a hook may block this) — use `.env.example` as the template.
- API keys managed via `backend/security/vault.py`.
- Input validation/sanitization in `backend/security/validation.py`; all user input sanitized before processing.
- Tool calls pass through `izn` permission checks; rate limits enforced by `wali`.
- Auth before the body: `credentials_first` middleware answers 401 for non-public `/api/*` without a valid credential before routing; roles are still checked by `enforce_api_access`. Tokens: `/api/auth/me`, `/api/auth/logout` (`everywhere`), revocations persisted in `revocations.json`. Limits with `Retry-After`/`RateLimit-*`: failed logins 5/min per IP and per username (`_login_failures`), chat messages 30/min per user (`_chat_messages`). CORS (`_OriginBoundCORS`) sends credentials only with a matched origin. Errors: one envelope (`error_body`: `detail` + `error{code,status,message}`) for HTTP, validation and unhandled errors. Public `/api/openapi.json` + `/api/docs` (Swagger CSP allows jsDelivr there only). `/api/agents` and `/api/status` take `detail=false` (summary) and agents `limit/offset`.

## Gotchas

- Docker reads `.env` for compose variable substitution — inline comments like `KEY=value # comment` get parsed as part of the value.
- Claude models use Anthropic only if `ANTHROPIC_API_KEY` starts with `sk-ant-`; otherwise they auto-route through OpenRouter.
- Claude requests never send `temperature`/`top_p`/`top_k` (API `2026-10-21` rejects them); `MIZAN_CHAT_TEMPERATURE` applies to other providers only. Effort comes from `MIZAN_CHAT_EFFORT`.
- Chat limits (steps, continuations, history budget, waits) are documented in `docs/chat-limits-and-metrics.md`; the step budget is no longer tied to the Nafs level.
- `DEFAULT_MODEL` controls the agent model (empty → provider default, `claude-opus-5-5` on Anthropic) — set it in `.env`. `LLM_PROVIDER=auto` (default) detects the provider from keys.
- Backend runs with `--reload`, so local edits in `backend/` take effect automatically.
- Admin-saved runtime settings (`runtime_settings.json`) override `.env` at startup; when a value seems ignored, check Settings → System settings for a "Set here" badge.
- `.env` values are NOT auto-loaded into `os.environ` — pydantic-settings reads them, but `providers.py` calls `load_dotenv()`.
- `.claude/` and `.claude.local.md` are gitignored — new local Claude Code config won't be committed; files already tracked there (`.claude/skills/mizan/SKILL.md`, kept identical to `.agents/skills/mizan/SKILL.md`) still are.
- The Ruh model and `ml` extra require PyTorch; `/api/ruh/*` and training endpoints are inert unless `RUH_ENABLED=true` and the model path is configured.
- Approvals are in-process futures: keep the backend at **one uvicorn worker** (the prod image does).
- Back up `$MIZAN_DATA_DIR/connectors.key` with the data volume; without it saved connector secrets cannot be decrypted.
- An ordinary chat must still send only `mizan_discover_tools` (`tests/test_dynamic_tool_catalog.py`); never pin new tools into every request.
- `backend/api/main.py` is a single large module — add routes there alongside existing groups rather than creating parallel routers.
