# MIZAN (ميزان) - Agentic Personal AI

> Quranic Cognitive Architecture (QCA) for human-like reasoning. Version 3.0.0.

## Quick Reference

- **Backend**: Python 3.11+ (FastAPI, Pydantic v2, aiosqlite, Click CLI) — fully async
- **Frontend**: React 19, TypeScript 7, Vite 8, Tailwind CSS 4 (`@tailwindcss/vite`, theme tokens in `src/index.css`: gold `primary`/`brand` on a neutral base, light + dark), shadcn/ui on Base UI (`src/components/ui/`), react-router 7 data router, zustand 5, TanStack Query 5, streamdown 2 (Shiki + KaTeX loaded only when an answer needs them), sonner, cmdk, recharts 3
- **AI Providers**: Anthropic (SDK 2.x, API `2026-10-21`, default `claude-opus-5-5`), OpenAI, OpenRouter, Ollama, + in-house **Ruh** model
- **Database**: SQLite via aiosqlite (default `data/mizan.db`)
- **Infra**: Docker Compose, Nginx; optional Ollama + ChromaDB profiles
- **ML**: PyTorch (optional `ml` extra) for the Ruh language model

## Commands

```bash
make setup          # First-time: install deps (.[dev]), pre-commit, frontend, .env
make dev            # Start backend + frontend dev servers (runs ./start.sh start)
make serve          # Backend only (uvicorn, --reload, port 8000)
make cli            # Interactive CLI chat (mizan chat)
make test           # pytest tests/ -v
make test-cov       # pytest with coverage (term + html)
make check          # lint + typecheck + test (full pipeline)
make lint           # ruff check backend/ tests/
make format         # ruff format + ruff check --fix
make typecheck      # mypy backend/ --ignore-missing-imports
make docker         # docker compose up -d --build
make docker-full    # + ollama and vector (ChromaDB) profiles
make docker-down    # Stop Docker
make clean          # Remove build/cache artifacts
make version        # Print VERSION
make release-patch  # Bump + changelog + tag + push (also -minor/-major/-beta/-rc)
```

**CLI** (`mizan <cmd>`, entry point `backend.cli:main`): `serve`, `chat`, `status`, `setup`, `doctor [--check|--fix]`, `version`.

Seeds in `tadbir/data/{lughah,qasd}` (licences in `data/lughah/LICENSES.md`); verified requests are learned per user (`qasd.learn`, Overlay). Fits are cached by corpus SHA-256 in `core/data/tamyiz.json`: after editing seeds run `cd backend && python -m core.tamyiz_cache` (`docs/fahm.md`)

## Architecture

7-layer **Quranic Cognitive Architecture (QCA)**:

| Layer | Module | Purpose |
|-------|--------|---------|
| 1-2 | `backend/perception/` | Sensory input: `vision`, `voice`, `nutq` (speech), `basirah` (insight) |
| 3 | `backend/qca/` | Cognitive integration: `engine`, `answer_engine`, `yaqin_engine` (certainty), `roots`, `cognitive_methods` |
| 4 | `backend/memory/` | Hierarchical memory: `dhikr`, `masalik`, `memory_pyramid`, `lawh_mahfuz`, `living_memory`, `knowledge_graph`, `vector_store` |
| 5 | `backend/reasoning/` | ReAct reasoning: `aql_engine`, `causal_engine`, `planner`, `context_manager` |
| 6 | `backend/agents/` | Autonomous agents with **Nafs** levels: `base`, `specialized`, `khalifah`, `shura_council`, `federation`, `perpetual_rotation` |
| 7 | `backend/core/` | Principles & cognition: `qalb`, `ihsan`, `tawbah`, `sabr`, `shukr`, `tawakkul`, `fitrah`, `fuad`, `lubb`, `basira`, `hawa`, `hikmah`, `hidayah`, `nafs_triad`, `ruh_engine`, `dream_engine`, `creativity`, `imagination`, `self_healing`, plus `plugins`, `hooks`, `middleware`, `events` |

### Ruh model (`ruh_model/`)
Pure-PyTorch transformer operating in **root-space** (`(root_id, pattern_id)` pairs) instead of BPE tokens. Requires the `ml` optional dependency group.

## Key Patterns

- **All backend I/O is async** (`async`/`await`).
- Pydantic models for every API request/response schema.
- JWT auth on endpoints; **Wali** rate-limiting; **Izn** permission gating before tool execution.
- **MIZAN directs, the LLM speaks**: requests Fahm recognises (compute, run code, write+run, build a web/Python project, Quran, hadith, Gregorian/Hijri dates, web search/read, recall, remember (the user's own words kept as a `chat:<id>` note), capabilities, a salam alone (`tadbir/tahiyya.py`: character Witten–Bell readers of salam formulas, returned salams and ordinary speech, plus a first-word view, fitted by leave-one-out; returned with the fuller greeting, 4:86, no model call; `MIZAN_TAHIYYA`)) are planned, executed and verified by Tadbir; Quran and hadith text and computed results never come from the model. Tests default to `MIZAN_ORCHESTRATION=llm` (conftest) except `tests/test_tadbir.py`.
- **Stateless evaluations** (`memory/stateless.py`): `stateless.bind()` stops cross-chat recall (`chat_context`), every learned-state write (`AdaptiveStateStore.put` is a no-op), memory's own writes (recall reads without an FSRS review or Masalik strengthening; no `task_history`, pathway or knowledge-graph entry) and training capture; bound for every Imtihan run, every Muqabala comparison, and chats sent with `stateless: true` (their messages are marked and never recalled, and "remember this" keeps no note); reported in `usage.memory`. Cross-chat recall (`Dhikr.recall_conversations`) returns only statements holding more than half of the information of the request's distinctive words (above an average word of general language), and never one Amanah reads as an injection.
- **Runs never queue behind each other**: `BaseAgent.execute` runs each request on its own copy of the agent (`_run_copy`: tool table rebound, config copied; `_finish_run` adds counters back and keeps lazily created attributes; `run_of(agent)` gives a request its own run). The settings lock (`agent_settings_lock`) is held only while a copy is taken. Imtihan runs tasks in parallel (`MIZAN_IMTIHAN_CONCURRENCY`, default 4).
- Agents run a real ReAct loop (`BaseAgent.think` → `_agentic_loop`), not single-shot calls; max iterations scale with **Nafs** level. Tools execute through `_execute_tool_safe` with input validation and self-healing (auto-install missing packages).
- **Nafs** levels (7-stage) evolve via `evolve_nafs()` / `DevelopmentalGate` based on success rate, task count, and hikmah.
- Real-time streaming via WebSocket and the `cognitive/thinking_stream` module.
- **Agentic coding** (`docs/agentic-coding.md`): chats send `permission_mode` (`auto_edits` | `ask` | `plan` | `auto`); mutating tools wait for `POST /api/chat/approvals/{id}` (git/sandbox reads never ask; "Always" persists per chat in `chat_always`, `/api/chat/{id}/always`; edit prompts carry a diff `preview`). Coding tools: `workspace_read/edit/write/glob/grep/run`, `todo_write`. A chat is bound to one project (`chat_sessions.workspace_id`, `PATCH /api/chat/{id}`) with a `turn` checkpoint before each message; checkpoints are content-addressed and restorable (`docs/coding-workspaces.md`), `.git` excluded. A coding request beyond MIZAN's recipes (React, a server, `package.json`) is handed to the model with `WORKSPACE_AGENT_TOOLS` only (`_workspace_only` in `agents/base.py`, Tadbir `_workspace_agent`): only in an interactive chat, `MIZAN_WORKSPACE_AGENT`; MIZAN checks the changed files and gives one repair turn; `plan_approved`/`fix` request fields are buttons. The frontend: `/code` lists projects and `/code/<id>` shows a project beside its chat (`pages/code/`, `react-resizable-panels`; `features/code/`: `ProjectWorkspace` Preview (Sandpack, Pyodide, a started dev server)/Code/Changes/Terminal, `ChangesTab` + lazy `MergeEditor` (`@codemirror/merge` Accept/Reject per hunk), `rewind.ts`); each chat keeps its own project in the browser (`utils/chatWorkspaces.ts`, the server's binding wins); `features/chat/ChatControls.tsx` holds the "Always" chips and "Approve plan and run".
- **Server sandbox sessions** (`workspace/sessions.py` on the runner, `workspace/session_client.py` + `api/workspace_sessions.py` in the backend): per-project hardened containers with an egress allowlist proxy, three-way file sync, dev-server previews at public capability URLs `/api/workspaces/preview/<cap>/<port>/` (always CSP-sandboxed), a PTY terminal at `/ws/workspaces/{id}/terminal`, and stdio MCP servers for non-admins. The container-side helper is stdlib-only `workspace/session_agent.py`. Each deploy moves the managed runner and runtime to the deployed commit's images (`setup_workspace_runner.py --upgrade`, run by `deploy_production.sh` under its lock) and keeps them only after a real session passes (npm/PyPI egress, confinement); otherwise the previous runner is restored and verified, exit 75/76 (`docs/runner-setup.md`).
- **Arabic-inspired naming** (consistency matters): Dhikr=memory, Masalik=memory paths, Wali=guardian, Izn=permission, Nafs=self/ego, Qalb=heart, Fuad=conviction, Lubb=metacognition, Basira=insight/discernment, Hawa=lower-pull/safety gate, Hikmah=wisdom, Ihsan=excellence, Tawbah=self-correction, Sabr=patience, Shura=council, Khalifah=steward agent, Yaqin=certainty, Ruh=spirit/model, Qadr=scheduling, Ummah=network, Bab=gateway.
- **al-Insān human-model** (`docs/quranic_human_model.md`): the Qur'anic anthropology MIZAN implements. Faculties (`basira`, `hawa`, `hikmah`, …) run inside `BaseAgent.execute()`; their reports come back as diagnostics in the result (`basira`, `hawa`, `hikmah_counsel`, `cognitive_result`), not applied to the prompt, and advisory observations reach the system prompt via `self._faculty_guidance`. No setting turns them into a gate (the old `DEEP_FACULTY_LOOP` was removed because nothing acted on it); the gates that act are Amanah, approvals, Hudud and Sidq.

## Security Notes

- Never edit `.env` directly (a hook may block this) — use `.env.example` as the template.
- API keys managed via `backend/security/vault.py`.
- Input validation/sanitization in `backend/security/validation.py`; all user input sanitized before processing.
- Tool calls pass through `izn` permission checks; rate limits enforced by `wali`.
- Auth before the body: `credentials_first` middleware answers 401 for non-public `/api/*` without a valid credential before routing; roles are still checked by `enforce_api_access`. Tokens: `/api/auth/me`, `/api/auth/logout` (`everywhere`), revocations persisted in `revocations.json`. Limits with `Retry-After`/`RateLimit-*`: failed logins 5/min per IP and per username (`_login_failures`), chat messages 30/min per user (`_chat_messages`). CORS (`_OriginBoundCORS`) sends credentials only with a matched origin. Errors: one envelope (`error_body`: `detail` + `error{code,status,message}`) for HTTP, validation and unhandled errors. Public `/api/openapi.json` + `/api/docs` (Swagger CSP allows jsDelivr there only). `/api/agents` and `/api/status` take `detail=false` (summary) and agents `limit/offset`.

## Gotchas

- Frontend colours come from the theme tokens (`bg-card`, `bg-muted`, `text-muted-foreground`, `border-border`, `text-brand`, `bg-primary`), not raw palette classes such as `text-gray-500`: their count in `frontend/.color-ratchet.json` may only go down. Heavy libraries (CodeMirror, xterm, Sandpack, recharts, Shiki, KaTeX) load on the route or answer that needs them; the entry stays under `.size-limit.json`.
- Docker reads `.env` for compose variable substitution — inline comments like `KEY=value # comment` get parsed as part of the value.
- Claude models use Anthropic only if `ANTHROPIC_API_KEY` starts with `sk-ant-`; otherwise they auto-route through OpenRouter.
- Claude requests never send `temperature`/`top_p`/`top_k` (API `2026-10-21` rejects them); `MIZAN_CHAT_TEMPERATURE` applies to other providers only. Effort comes from `MIZAN_CHAT_EFFORT`.
- Chat limits (steps, continuations, history budget, waits) are documented in `docs/chat-limits-and-metrics.md`; the step budget is no longer tied to the Nafs level.
- `DEFAULT_MODEL` controls the agent model (empty → provider default, `claude-opus-5-5` on Anthropic) — set it in `.env`. `LLM_PROVIDER=auto` (default) detects the provider from keys.
- Backend runs with `--reload`, so local edits in `backend/` take effect automatically.
- Admin-saved runtime settings (`runtime_settings.json`) override `.env` at startup; when a value seems ignored, check Settings → Developer → System settings for a "Set here" badge.
- `.env` values are NOT auto-loaded into `os.environ` — pydantic-settings reads them, but `providers.py` calls `load_dotenv()`.
- `.claude/` and `.claude.local.md` are gitignored — new local Claude Code config won't be committed; files already tracked there (`.claude/skills/mizan/SKILL.md`, kept identical to `.agents/skills/mizan/SKILL.md`) still are.
- The Ruh model and `ml` extra require PyTorch; `/api/ruh/*` and training endpoints are inert unless `RUH_ENABLED=true` and the model path is configured.
- Approvals are in-process futures: keep the backend at **one uvicorn worker** (the prod image does).
- Back up `$MIZAN_DATA_DIR/connectors.key` with the data volume; without it saved connector secrets cannot be decrypted.
- An ordinary chat must still send only `mizan_discover_tools` (`tests/test_dynamic_tool_catalog.py`); never pin new tools into every request.
- `backend/api/main.py` is a single large module — add routes there alongside existing groups rather than creating parallel routers.
